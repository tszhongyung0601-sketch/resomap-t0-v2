雷達：每天怎麼撈、怎麼回

在脆上找到正在問「台灣怎麼玩」的人，把他排進佇列，然後由人寫回覆送出。 機器只負責找——這一整套裡沒有任何一行程式碼能送出貼文，那是刻意的。

00

先用假資料看一眼

1 分鐘

不需要任何設定、不會碰到任何真人。跑完你就知道整條線長什麼樣。

$npm run radar:demo
$npm run radar:serve

瀏覽器會自己開 localhost:5174，上面有 9 則卡片。隨便按幾下 「回過了」「不回」，重新整理——消失的那幾則就是寫進 .radar-seen.json 了。 Ctrl+C 關掉。

看完要清掉

demo 的紀錄會混進第一週的統計，讓 radar:stats 算出來的數字失真。

$rm .radar-queue.json .radar-seen.json .radar-log.json
01

撈貼文：手動進料

每天 10 分鐘

Threads 的關鍵字搜尋權限要送 App Review、等一到三週。但第一週要回答的問題 其實不需要 API：一天到底有幾則值得回。所以先用人力撈。

1 · 建進料檔

$cp scripts/radar/intake.example.txt .radar-intake.txt

打開它，把範例那兩則刪掉。# 開頭的說明可以留著，解析時會自動跳過。

2 · 在脆上搜這十條

台灣 行程 推薦 台灣自由行 求推薦 第一次來台灣 台北 行程 請益 台中 一日遊 推薦 台南 兩天一夜 高雄 行程 推薦 花蓮 行程 求推薦 台湾 行程 推荐 台湾自由行 求推荐

最後兩條是簡體。脆不做繁簡轉換，「台湾自由行」跟「台灣自由行」是兩批不同的結果， 而陸客那一群幾乎都用簡體搜。

3 · 整段複製貼進去，每則之間放一行 ---

@（帳號略） 2小時 大陸人到台灣玩 9.18早上到台北，9.24/25從高雄起飛… --- @another_person 香港人第一次來台灣…

@帳號、連結、2小時 這三行都可以省略，懶得複製就只貼內文。 有貼連結最好——審的時候可以直接跳過去。

一次貼 20–30 則，不要挑。你覺得不該回的也照貼。第一週是在測分類器， 不是在測你的眼光；而分類器漏掉什麼，只有你把它漏掉的東西也餵進去才看得出來。

4 · 跑

$npm run radar:intake

會印出三個數字，以及一份「被擋掉的」清單。那份清單要看。 如果裡面有你覺得該回的，去 scripts/radar/classify.mjs 補詞庫再重跑一次—— 詞庫補完立刻生效，不用改別的地方。

$npm run radar:serve
02

審核頁怎麼按

每張卡片四個區塊，從上到下讀：

區塊它在說什麼
分數 + 理由為什麼它排在這個位置。理由講不通就不要信那個分數
能答 / 答不了綠色是 App 接得住的；紅色是你要在回覆裡老實講的
虛線框草稿看到 ⟨⟩ 就代表還沒完成
四顆按鈕開啟原貼文 · 複製草稿 · 回過了 · 不回

動作順序

複製草稿 → 開啟原貼文 → 在脆上貼 → 填掉 ⟨⟩ → 送出 → 回來按「回過了」。

頁面最上面那行「還剩 X 則額度」是真的上限，歸零就今天收工。 按「回過了」才會扣額度、才會讓那則從佇列消失——忘記按，明天它會再出現一次。

三個分級

立刻看

≥ 70 分

跨城市、外地旅客、帶明確日期、剛貼不久。兩小時內回還看得到。

今天看

45 – 69 分

訊號齊但少一兩項——多半是單一城市，或貼了半天。

有空看

< 45 分

單點問題、已經很多人回答、或貼了超過一天。額度有剩再說。

分數是怎麼來的

老闆看到的那則 · @（帳號略） · 2 小時前 「大陸人到台灣玩。9.18 早上到台北，9.24/25 從高雄起飛，會到台北台中台南玩， 想請教這幾個城市有什麼推薦玩的地方嗎（順便求一下高 cp 值青旅推薦）。 以及一個人就普普通通吃飯一天的預算？」

有求助句式：請教、想請、有什麼+20
跨 4 個城市：台北、台中、台南、高雄+28
外地旅客：陸人、大陸人+18
帶明確日期 9.18 / 9.24+15
2 小時前+10
在問一整趟行程未命中
立刻看91

「在問一整趟行程」沒有加到分——那則從頭到尾沒寫「行程」兩個字， 他是用「會到台北台中台南玩」講的。最有價值的貼文不會用你預期的詞來問， 所以分數靠好幾個獨立訊號疊加，不靠單一關鍵字。

03

填草稿：這步最重要

草稿只是讓你少打幾個字，它不是回覆。沒填完就送出的草稿，跟業配機器人沒有區別。

三條不能破的

  1. ⟨⟩ 填不出來就按「不回」。 填不出具體內容，代表你對這題沒有東西可以給，那則回覆就只是廣告。
  2. 紅色那行不要刪。 「訂房我們沒做」就是這則回覆跟業配之間唯一的差別。他問了四件事，我們只接得住三件，那就講三件。
  3. 連結永遠最後一句，utm_ 那串不要砍。 砍了第三週就量不到點擊，也就永遠不知道人點進來之後留不留得住。
04

一週後結算

7 天後
$npm run radar:stats

它會直接給結論，不用你自己判斷。門檻看的是「每天幾則 hot」：

< 3 則 別送 App Review天花板太低。這條路的價值上限就是這個數字，時間花在別的獲客管道。
3 – 10 則 送審，但回覆繼續人工寫人回得完，而且回得比機器好。掃描自動化，送出不自動化。
> 10 則 送審，並認真討論上限人工審開始變成瓶頸了。動那個 5 則上限之前，先把下面六條規矩讀一遍。

它還會另外提醒一件事：如果「不回」按得比「回過了」多兩倍以上， 那是佇列在放垃圾進來，該去收緊 classify.mjs 的門檻，不是怪需求不存在。

05

接上 API 之後

送審通過

Meta 開發者後台申請 threads_basic ＋ threads_keyword_search，把短期 token 換成 60 天長期 token。

>$env:THREADS_TOKEN = "你的長期token"; npm run radar:scan

之後用 Windows 工作排程器每 30 分鐘叫一次 npm run radar:scan， 你一天開一次 npm run radar:serve 審就好。進料那一步不用做了， 但填草稿跟送出永遠是人——這一點不會因為 API 通了而改變。

六條規矩

這幾條比程式碼重要。程式只是讓你不用自己去滑。

  1. 一天最多回 5 則，超過就停。
  2. 不回同一個人第二次。
  3. 第一句一定是對他問題的具體回答，連結放最後一句。
  4. 答不了的事要講出來。
  5. 表明身分：「我們做的 ResoMap」，不裝路過的熱心網友。
  6. 被嫌煩就道歉、刪留言、退出那串。不要辯。

為什麼沒有「送出」按鈕

脆的社群會公審。一個只會貼連結的帳號，兩天內就會被截圖轉發嘲笑， 而且會直接掛在品牌名字上。

Meta 條款禁止自動化濫發。罰則不是刪你那則留言，是收掉整個 App 的 API 權限——連掃描一起沒。

回錯的成本不對稱。漏掉十則沒人知道；回錯一則（徵人文、代購文、 或有人在問牙醫）會被截圖。所以分類器寧可放過，不可放錯。

出狀況時

症狀原因
搜尋回來幾乎都是你自己的貼文 threads_keyword_search 還沒過審。它不會報錯，只會安靜地只搜自己——這是最坑的一點，看起來像 query 寫錯
同一則一直重複出現 沒按「回過了」，或 .radar-seen.json 被刪掉了
radar:serve 回 404 還沒跑 radar:intake 或 radar:scan，佇列檔不存在
統計數字看起來太漂亮 demo 的紀錄沒清掉。刪 .radar-log.json 重新累積
額度用完了 脆的查詢額度是跨 app 共用的滾動 24 小時。掃描會自己停下來，不是崩潰
有人嫌你煩 道歉、刪留言、退出那串。不要辯
所有 .radar-* 產出檔都在 .gitignore 裡——裡面是真人的貼文內容跟帳號，不會被 commit 上去。 審核伺服器只綁 127.0.0.1，不會出現在區網上。 完整技術說明見 RADAR_MVP.md。
這頁掛在正式網域上但標了 noindex——有連結的人看得到，搜尋引擎不收錄。引文為改寫摘要並已移除原帳號。
